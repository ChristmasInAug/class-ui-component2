# handoff — 세션 인계

세션을 넘길 때 현재 상태를 한 파일에 스냅샷으로 남긴다. 목적은 "다음 사람이 뭘 알아야 이어갈 수 있는가"를 빠짐없이, 근거와 함께 적는 것이다.

## 핵심 원칙

- **✅ 완료는 검증된 것만.** 각 항목에 증거(실행한 명령, 파일:라인, 테스트 결과)를 반드시 붙인다. 증거가 없으면 ✅가 아니다 — ⏳로 내린다. "되겠지"로 완료 표시 금지.
- **❌ 는 시도했지만 실패/막힌 것 + 원인.** 다음 세션이 같은 막다른 길을 반복하지 않게 한다.
- **⏳ 는 바로 이어갈 다음 단계 + 시작점(파일/명령).** 아직 손 안 댄 것도 빠짐없이 넣는다.
- **이어받는 사람 관점으로 쓴다.** "내가 뭘 했나"가 아니라 "다음 사람이 뭘 알아야 이어가나".
- **간결·스캔 가능하게.** 각 항목 한 줄, 체크박스 형태(`- [x]` / `- [ ]`). 산문 단락 금지.
- **기존 인계 파일이 있으면 덮어쓰지 말고 갱신한다.** 끝난 ⏳ 항목은 증거를 확인한 뒤 ✅로 옮기고, 여전히 유효한 미완료 항목은 ⏳로 carry-forward하고, 더 이상 유효하지 않은 항목은 삭제한다.

## 실행 순서

1. **대상 파일 결정.** 사용자가 경로를 지정하지 않았으면 저장소 루트의 `.handoff.md`를 기본값으로 쓴다(사용자가 `STATE.md` 등 다른 이름을 지정하면 그것을 쓴다).
2. **기존 파일이 있으면 먼저 읽는다.** 있으면 Edit으로 갱신(끝난 항목 승격, 유효한 미완료 carry-forward, 새 실패/다음 단계 추가), 없으면 Write로 새로 만든다.
3. **컨텍스트를 실제로 수집한다 — 추측 금지.** 아래를 실행해 결과를 확인한 뒤 채운다:
   ```
   date '+%Y-%m-%d %H:%M'
   git branch --show-current
   git status --short        # 신규/untracked 포함 변경 요약
   git diff --stat           # tracked 변경 요약
   ```
   더불어 이번 세션(대화)에서 실제로 실행한 빌드/테스트/명령의 실제 출력을 근거로 사용한다 — 실행하지 않은 것을 성공했다고 적지 않는다.
4. **아래 형식 그대로 작성한다.**

```markdown
# 🤝 Handoff — <한 줄 현재 상태 요약>

> 갱신: <YYYY-MM-DD HH:MM> · 브랜치: `<branch>` · 변경: `<git status --short 요약 (신규/untracked 포함) — tracked 변경은 git diff --stat>`

## ✅ 완료 (검증된 것만)
<!-- 증거 없는 항목은 여기 두지 말 것. 비었으면 `- 없음` -->
- [x] <한 일> — 증거: `<실행한 명령 / 파일:라인 / 테스트 결과>`

## ❌ 시도 → 실패 / 막힘 (반복 금지)
<!-- 시도한 접근 + 왜 안 됐는지 원인. 비었으면 `- 없음` -->
- [ ] <시도한 접근> — 원인: <왜 안 됐나> → 다음 대안: <있으면>

## ⏳ 다음 할 일 / 미착수
<!-- 바로 이어갈 다음 단계. 시작점(파일/명령)을 함께. -->
- [ ] <다음 단계> — 시작점: `<파일 / 명령>`

## 📌 컨텍스트 메모
<!-- 이어받는 사람이 모르면 헤맬 것: 결정·제약·함정·환경 설정. 비었으면 이 섹션 생략 -->
- <결정/제약/주의 한 줄>
```

5. **작성 후 파일 경로를 한 줄로 사용자에게 보고한다.** 내용을 다시 채팅에 통째로 출력하지 않는다 — 파일이 곧 산출물이다.

## 주의사항

- ✅/❌/⏳ 각 섹션이 비어 있으면 반드시 `- 없음`으로 명시한다(섹션 자체를 생략하지 않는다). 단, 📌 컨텍스트 메모는 내용이 없으면 섹션째 생략해도 된다.
- 항목은 항상 한 줄로 — 여러 줄에 걸친 설명이 필요하면 근거를 더 짧게 요약하거나 파일 경로 참조로 대체한다.
- 이 파일(`.handoff.md` 등)이 민감한 내용(토큰, 개인정보)을 담지 않는지 확인한다 — 저장소가 공개될 경우 그대로 노출된다.
